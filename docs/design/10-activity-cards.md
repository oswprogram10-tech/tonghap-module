# 설계 10: 활동 카드 라이브러리와 꼬리 잇기 추천

단원 빌더에서 차시를 빈칸부터 쓰지 않도록, 주제책별 **활동 카드**에서 골라 차시를 만든다. 꼬리 잇기로 다음 차시를 정할 때는 학생 질문과 단원의 빈 곳(성취기준·필수 편성)을 보고 카드 3개를 추천한다. 언어 모델 없이 규칙으로 한다.

## 데이터

- 기본 카드: `data/activities/activities.json`(스키마 `data/activities/schema/activities.schema.json`, 검증 `scripts/validate-activities.mjs`, `validate:data`에 포함). 주제책 16권 × 6장 안팎(바 1, 슬 2, 즐 1, 안전 더하기 1, 메이킹북 1). 놀이는 `data/plays`에 있으므로 활동 카드에는 넣지 않는다.
- 교사 카드: 새 표(마이그레이션 7)

```sql
CREATE TABLE custom_activities (
  id TEXT PRIMARY KEY,                 -- 'custom-<uuid>'
  data TEXT NOT NULL,                  -- 스키마 항목 하나와 같은 모양
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- 차시가 어느 카드에서 왔는지: `unit_sessions`에 `activity_id TEXT`(NULL 허용) 칼럼 추가(같은 마이그레이션). 추천에서 "이미 쓴 카드"를 빼는 데 쓴다.

## 명령

| 명령 | 입력 | 출력 |
|---|---|---|
| `activity_custom_list` / `activity_custom_save` / `activity_custom_delete` | 놀이 카드와 같은 방식 | |
| `activity_recommend` | `{ unitId, afterSessionId?, questions? }` | `{ activity, score, reasons: string[] }[]` 최대 3개 |

- 기본 카드는 프런트엔드가 빌드 때 JSON으로 읽고(놀이 카드와 같은 방식), Rust도 `include_str!`로 읽어 추천 계산에 쓴다.
- 교사 카드 검증은 Rust에서 스키마와 같은 규칙(주제책·성취기준 대응 포함).

## 추천 규칙 (`activity_recommend`)

후보: 그 단원 주제책의 카드(기본 + 교사), 단원에서 이미 쓴 카드(`activity_id`)는 뺀다. 주제책이 없는 단원이면 학년의 모든 주제책 카드. 점수(높은 순, 같으면 id 순으로 결정적):

| 항목 | 점수 | 이유 문구 |
|---|---|---|
| 학생 질문(`questions`, 없으면 `afterSessionId` 차시의 `student_questions`)의 낱말이 카드 `keywords`·제목에 있음 | 낱말당 +3(최대 +9) | "학생 질문의 '개미'와 이어져요" |
| 카드의 성취기준이 단원에서 아직 한 번도 다루지 않은 것 | 기준당 +2 | "[2슬02-04]를 아직 다루지 않았어요" |
| 필수 편성 부족: 안전 4차시·메이킹북 3차시 미만이고 카드 종류가 그것 | +3 | "안전 더하기가 2차시 더 필요해요" |
| 앞 차시와 같은 교과가 아님(교과를 고르게) | +1 | |

낱말 맞추기: 질문을 공백·문장부호로 나누고 조사를 뗀(평어 검사에서 쓰는 조사 떼기 재사용) 2글자 이상 낱말이 카드 키워드의 시작과 같거나 포함되면 일치.

## 화면

- **차시 추가**(단원 화면의 「차시 추가」): 두 갈래 — 「빈 차시」 / 「활동 카드에서 고르기」. 카드 고르기는 이 단원 주제책 카드 목록(종류 거르기: 전체·일반·안전·메이킹북), 카드에 제목·교과·시간·성취기준 칩·진행 순서 미리보기. 고르면 차시 편집 창이 채워진 채 열림: 제목, 활동 내용(진행 순서를 번호 목록 글로), 시간, 종류, 성취기준(방식은 기본 `focus`, 교사가 바꿈), `activityId`.
- **꼬리 잇기 창**(「마치고 다음 차시 잇기」): 학생 질문을 입력하면(입력이 멈추고 0.5초 뒤) 추천 카드 3장과 이유를 보여 준다. 카드를 누르면 다음 차시 제목·단계가 그 카드로 채워지고, 저장 시 새 차시에 카드 내용이 들어간다(질문은 설계 03대로 활동 내용 첫머리에).
- **교사 카드 관리**: 단원 목록 화면의 「활동 카드 관리」(놀이 관리와 같은 모양) — 새로 만들기, 기본 카드 복사해 고치기, 삭제.

## 테스트 기준

Rust: 마이그레이션 7(버전 6 데이터 유지), 버전 6 백업 복원. 교사 카드 저장·검증(다른 주제책 성취기준 거부). 추천: 질문 낱말 일치 점수와 이유, 아직 안 다룬 성취기준 가점, 안전·메이킹북 부족 가점, 쓴 카드 제외, 결정적 순서, 주제책 없는 단원. 카드로 만든 차시에 `activity_id` 저장.
프런트엔드 스모크: 카드에서 차시 만들기, 꼬리 잇기에서 질문 입력 → 추천 → 카드로 다음 차시.
