# 설계 06: 관찰 기록 검색

기록이 쌓이면(학급 25명 × 1년 → 수백~수천 건) "지난달 소방서 견학 때 누가 무슨 말을 했지?" 같은 질문에 답할 수 있어야 한다. 메모·음성 자막·태그·차시 제목에서 글자로 찾고, 기존 거르기(학생·주제책·성취기준)와 날짜 범위를 함께 쓴다.

## 방식

- **SQLite `LIKE`로 부분 일치 검색**. FTS5는 쓰지 않는다: 기본 토크나이저는 한국어 조사("블록을")를 분리하지 못하고, trigram 토크나이저는 두 글자 낱말("블록")을 찾지 못한다. 학급 단위 데이터(수천 행)에서는 LIKE로 충분히 빠르다.
- 검색어는 공백으로 나눈 낱말들이고 **모두 들어 있어야**(AND) 한다. 각 낱말은 다음 중 **하나라도**에 들어 있으면 된다(OR): 관찰 메모, 그 관찰 음성 첨부의 자막, 태그, 연결된 차시 제목, 함께 기록된 학생 이름.
- LIKE 특수문자(`%`, `_`, `\`)는 이스케이프(`ESCAPE '\'`). 낱말은 최대 5개, 각 30자.
- 삭제된 관찰은 제외(휴지통 보기에서는 휴지통 안에서 검색).

## 명령 변경

`observation_list`의 `ObservationQuery`에 선택 필드 추가(기존 호출은 그대로 동작):

- `text?: string` — 검색어
- `from?: string`, `to?: string` — `'YYYY-MM-DD'`, 관찰 시각의 로컬 날짜 기준, 양 끝 포함
- `hasPhoto?: boolean`, `hasAudio?: boolean`

응답 `Observation`에 `matches?: { field: 'note' | 'transcript' | 'tag' | 'session' | 'student', snippet: string }[]` 추가(검색어가 있을 때만). `snippet`은 일치한 곳 앞뒤 20자(문자 기준, 말줄임표 포함). 일치 위치 표시는 프런트엔드가 snippet 안에서 다시 찾아 `<mark>`로 감싼다.

새 명령 `observation_count`: 같은 쿼리로 전체 개수(페이지 넘김 없이) — 「검색 결과 N건」 표시용.

## 화면

- **관찰 기록 탭**의 「최근 기록」 칸을 **「기록 찾기」**로 바꾼다.
  - 검색창(큰 입력, 오른쪽 「찾기」·「지우기」). 입력 후 Enter 또는 「찾기」.
  - 거르기 줄: 학생(선택), 주제책(선택), 기간(이번 주·이번 달·이번 학기·직접 입력), 사진 있음·음성 있음 토글.
  - 결과: 「N건」 + 기존 기록 카드. 검색어가 있으면 카드 아래에 일치한 곳(snippet)을 종류 표시와 함께 보여 주고 일치 글자를 강조.
  - 아무 조건이 없으면 지금처럼 최근 20건.
- **포트폴리오 학생 타임라인**에도 검색창 하나(그 학생 기록 안에서 찾기). 같은 명령에 `studentId`를 넣는다.
- 결과 카드를 누르면 기존 수정 창.

## 테스트 기준 (Rust)

- 메모·자막·태그·차시 제목·학생 이름 각각으로 찾기.
- 여러 낱말 AND, 낱말마다 다른 곳에서 일치해도 찾음.
- `%`, `_`가 든 검색어가 와일드카드로 동작하지 않음.
- 날짜 범위 양 끝 포함, 사진·음성 있음 거르기, 기존 학생·주제책·성취기준 거르기와 함께.
- 삭제된 관찰 제외, 휴지통 모드에서는 휴지통 안에서만.
- `observation_count`가 페이지 넘김과 무관하게 전체 개수.
- snippet: 앞뒤 20자, 문자열 경계(앞이 짧을 때), 한글이 깨지지 않음(바이트가 아니라 문자 기준).
