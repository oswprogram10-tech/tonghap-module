# 설계 20: PC 안 기록 DB 암호화 (SQLCipher + 윈도우 DPAPI)

`docs/PLAN.md` 기술 구성의 「윈도우 DPAPI로 암호화 키 보관」을 구현한다. 지금은 백업 파일만 암호화되고 `<로컬 데이터>/data/tonghap.db`는 평문이다. 노트북 분실, 디스크를 떼어 읽기, 다른 프로그램이 파일을 복사해 가는 경우에 이름·메모·자막이 그대로 보인다.

## 범위

- **이번:** 기록 DB(이름, 관찰 메모, 자막, 평어, 리포트 기록)를 SQLCipher(AES-256)로 암호화한다.
- **이번이 아님:** 사진·음성 파일(`media/`). 화면이 asset 프로토콜로 바로 읽으므로 암호화하려면 복호화 프로토콜이 따로 필요하다. 다음 단계로 미루고 정보 화면·개인정보 안내에 그대로 적는다. 로그는 이미 이름을 가린다.

## 1. 키

- 32바이트 난수 키. `<로컬 데이터>/data/db.key`에 저장한다.
- **윈도우:** `CryptProtectData`(현재 사용자 범위, `CRYPTPROTECT_UI_FORBIDDEN`, 추가 엔트로피 = 앱 식별자 문자열)로 보호한 바이트를 저장한다. 읽을 때 `CryptUnprotectData`. `windows-sys`의 `Win32_Security_Cryptography` 기능 추가.
- **윈도우 밖(개발·리눅스 CI):** 같은 파일에 앞머리 `PLAIN1`을 붙인 원본 키를 저장한다(유닉스는 권한 0600). 윈도우 빌드가 `PLAIN1` 파일을 만나면 거부한다(그 경우는 버그).
- 키 파일 형식에 버전 머리(`DPAPI1`/`PLAIN1`)를 둔다.
- 키는 `PRAGMA key = "x'<64 hex>'"`로 넘긴다(문자열 키 유도 없이 원본 키). 키를 로그·오류 문구·진단 파일에 남기지 않는다.

## 2. 의존성

- `rusqlite` 기능 `bundled` → `bundled-sqlcipher-vendored-openssl`. 윈도우 MSVC·리눅스 모두 OpenSSL을 소스로 함께 빌드(빌드 시간 증가, perl 필요 — GitHub 러너에 있음). CI에서 빌드되는지 먼저 확인한다.
- 라이선스 파일 재생성(`npm run licenses:full`): SQLCipher(BSD), OpenSSL(Apache-2.0).
- 실패 시 대안(구현 전에 판단해 보고): OpenSSL 빌드가 막히면 중단하고 보고한다. 임의로 다른 암호화 방식을 고르지 않는다.

## 3. 열기 (`db::open`) — 상태별 동작

| DB 파일 | 키 파일 | 동작 |
|---|---|---|
| 없음 | 없음 | 새 키 → 새 암호화 DB |
| 없음 | 있음 | 그 키로 새 암호화 DB |
| 평문(첫 16바이트가 `SQLite format 3\0`) | 없음/있음 | **전환**(아래 4) 후 열기 |
| 암호화 | 있음, 풀림 | 열기. 키가 맞는지 `SELECT count(*) FROM sqlite_master`로 확인 |
| 암호화 | 없음, 또는 DPAPI가 못 풂, 또는 키가 틀림 | **절대 새 DB를 만들지 않는다.** `DbLocked` 상태로 앱을 띄워 안내 화면(아래 6) |

- `TONGHAP_DATA_DIR` 디버그 장치는 그대로 동작해야 한다(E2E).
- `test_conn()`(메모리 DB)과 기존 테스트는 키 없이 그대로 둘 수 있다(메모리 DB 암호화 불필요). 파일 DB 테스트는 새 열기 함수를 쓴다.

## 4. 평문 → 암호화 전환 (첫 실행 한 번) — 데이터 손실이 없어야 함

1. 평문 DB를 열고 `PRAGMA wal_checkpoint(TRUNCATE)`, `PRAGMA integrity_check` = ok 확인. 아니면 전환하지 않고 평문으로 계속(로그 + 정보 화면 경고).
2. 디스크 여유가 DB 크기 × 2보다 작으면 전환 미룸(같은 처리).
3. `tonghap.db.enc-tmp`를 만들고 `ATTACH ... KEY "x'..'"` → `SELECT sqlcipher_export('enc')` → `user_version` 복사.
4. 새 파일을 키로 다시 열어 `integrity_check` ok, **모든 사용자 표의 행 수가 원본과 같음** 확인. 다르면 tmp를 지우고 평문으로 계속.
5. 바꾸기: 평문 `tonghap.db`(+ -wal, -shm) → `tonghap.db.plain-old`, tmp → `tonghap.db`. 새 DB를 열어 다시 확인. 실패하면 원래대로 되돌린다(설계 02 swap의 「놓은 것만 지움」 원칙).
6. 성공하면 `tonghap.db.plain-old`를 지운다(덮어쓰기 후 삭제까지는 하지 않음 — SSD에서는 의미가 적다. 문서에 적음).
7. 중간에 앱이 꺼져도 다음 실행에서 이어지도록: 시작 시 `tonghap.db.enc-tmp`가 남아 있으면 지우고 처음부터. `tonghap.db.plain-old`가 있고 `tonghap.db`가 암호화로 잘 열리면 plain-old 삭제, `tonghap.db`가 없으면 plain-old를 되돌려 놓고 다시 전환.
8. **예전 복원 보관 폴더**(`before-restore-*`)의 평문 DB도 같은 방식으로 암호화한다(실패해도 앱 시작은 막지 않음, 로그).
9. 전환 시작·결과를 로그에 남긴다(경로·키 없이).

## 5. 백업·복원

- 백업 파일 형식은 **바꾸지 않는다**(보관함 안 `tonghap.db`는 평문 SQLite, 보관함 전체가 age로 암호화). 그래서 예전 앱 버전과 백업 형식이 같고, 다른 PC(다른 키)에서 복원할 수 있다.
- 만들기: `VACUUM INTO` 대신 평문 임시 DB로 `sqlcipher_export`(KEY '')를 만든다. 임시 파일은 데이터 폴더 안 임시 폴더에 두고 끝나면(실패해도) 지운다. 시작 시 남은 임시 폴더를 지운다(이미 있다면 그 정리 경로 재사용).
- 복원: 풀린 평문 DB를 검사·마이그레이션(지금처럼) → **현재 키로 암호화 DB로 내보낸 뒤** swap. staging의 평문 파일은 끝나면 지운다.
- `before-restore-*`에 옮겨 두는 현재 DB는 이미 암호화되어 있으므로 그대로.

## 6. 화면

- **정보 화면** 「기록 보호」: 「기록 데이터베이스가 이 PC의 윈도우 계정에 묶인 키로 암호화되어 있습니다. 사진·음성 파일은 아직 암호화되지 않습니다.」 전환 실패 상태면 경고와 이유.
- **열 수 없음 화면**(`DbLocked`): 「이 윈도우 계정에서 기록을 열 수 없습니다. 다른 윈도우 계정으로 로그인했거나, 관리자가 윈도우 암호를 재설정한 경우일 수 있습니다. 원래 계정으로 로그인해 보거나, 백업 파일로 복원하세요.」 + 「백업 파일로 복원」(기존 복원 흐름, 열 수 없는 DB는 `unreadable-<시각>` 폴더로 옮겨 보관) + 「문의용 진단 파일 만들기」. 다른 탭은 막는다.
- 진단 파일 `about.json`에 `dbEncrypted: true|false`, `dbState: "ok"|"plain"|"locked"`.

## 테스트 기준

- 키: DPAPI 왕복(`#[cfg(windows)]`, 윈도우 CI에서 돎), 다른 엔트로피로는 못 풂, `PLAIN1` 왕복(비윈도우), 손상된 키 파일 → 오류.
- 새 DB 파일의 첫 16바이트가 `SQLite format 3\0`이 아님, 파일 바이트에 학생 이름(UTF-8)이 없음.
- 전환: `seed_year` 평문 DB → 전환 후 모든 표 행 수 같음, 평문 파일 없음. 단계별 실패 주입(export 실패, 행 수 불일치, 이름 바꾸기 실패) → 평문 DB가 그대로 열리고 데이터 같음. 중간 종료 흉내(enc-tmp 남음, plain-old만 남음) → 다음 열기에서 복구.
- 키 없음/틀린 키로 암호화 DB → `DbLocked`, 파일이 바뀌지 않음(해시 같음), 새 DB를 만들지 않음.
- 백업 → 복원 왕복(암호화 DB), 예전 평문 백업(v8, v9 형식) 복원 후 DB가 암호화됨, 백업 보관함 안 DB는 평문 SQLite(형식 유지), 임시 평문 파일이 남지 않음.
- `before-restore-*`의 평문 DB 암호화.
- 성능: `tests/perf.rs` 상한 안(SQLCipher로 느려진 정도를 보고).
- 기존 테스트 전부, E2E(윈도우) 통과.
