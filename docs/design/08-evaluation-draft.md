# 설계 08: 생기부 평어 초안 (준비 단계)

학기 말 교과학습발달상황(바른 생활·슬기로운 생활·즐거운 생활) 서술형 평어 초안을, 1년간 쌓인 **실제 기록을 근거로** 교사 PC 안에서 만든다.
이 문서는 전체 구조와, 언어 모델 없이 먼저 만들 수 있는 부분(근거 모으기·검사·화면·템플릿 초안)을 정한다. 로컬 언어 모델 학습과 연결은 뒤 단계(설계 09 이후)에서 한다.

## 원칙

1. **근거 없는 문장은 없다.** 초안의 모든 문장은 기록(관찰, 자막, 차시, 습관 실천율) 하나 이상을 가리킨다. 가리킬 근거가 없으면 그 문장을 만들지 않는다.
2. **교사가 확정한다.** 앱은 초안만 만들고, 교사가 고치고 「확정」해야 복사·내보내기가 된다. 화면에 "초안입니다. 교사의 관찰과 판단으로 고쳐 주세요"를 늘 보인다.
3. **서열·등급 표현 금지.** "가장", "1등", "뛰어나게 우수" 같은 비교·서열 표현과 점수는 쓰지 않는다(2022 개정 통합교과 평가 지침).
4. **다른 아이 정보 금지.** 다른 학생 이름, 가족의 직업·경제 상황, 사교육·외부 기관 이름은 넣지 않는다. 금지 표현 목록은 데이터 파일로 두고 학교 기재요령에 맞춰 교사가 고칠 수 있게 한다.
5. **아이 데이터는 PC 밖으로 나가지 않는다.** 학습용 데이터는 실제 기록이 아니라 합성 데이터와 교사가 직접 쓴 예시로 만든다.

## 전체 흐름

```
기록 DB ──(1) 근거 모으기──▶ 근거 묶음(JSON) ──(2) 초안 생성──▶ 문장 + 근거 id
                                              ├ 템플릿(지금)
                                              └ 로컬 언어 모델(나중, 같은 입출력)
      ──(3) 자동 검사──▶ 경고 표시 ──(4) 교사 편집·확정──▶ 복사(NEIS 붙여넣기)
```

생성기(템플릿이든 언어 모델이든)는 **같은 입력(근거 묶음)과 같은 출력(문장 목록 + 근거 id)**을 쓴다. 그래서 지금 만드는 화면·검사는 언어 모델이 붙어도 그대로 쓴다.

## (1) 근거 모으기 — `evidence_bundle`

입력: `{ studentId, subject: '바'|'슬'|'즐', from, to }`

출력(근거 묶음, 언어 모델 입력 형식과 동일):

```json
{
  "student": { "alias": "학생" },
  "subject": "슬",
  "period": { "from": "2027-03-02", "to": "2027-07-18" },
  "evidence": [
    {
      "id": "o:3f2a…",
      "kind": "observation",
      "date": "2027-04-10",
      "topic": "탐험",
      "standards": ["[2슬02-04]"],
      "tags": ["탐구", "질문"],
      "text": "우주 영상을 보고 '별은 왜 반짝여요?'라고 질문함",
      "quote": "별은 왜 반짝여요? 낮에도 있어요?",
      "together": true
    },
    { "id": "h:9b1c…", "kind": "habit", "title": "사물함 정리하기", "doneDays": 18, "schoolDays": 20 },
    { "id": "s:77de…", "kind": "session", "date": "2027-05-02", "topic": "마을", "title": "마을 안전 지도 만들기", "standards": ["[2슬02-01]"] }
  ],
  "standardsText": { "[2슬02-04]": "궁금한 세계를 다양한 매체로 탐색한다." }
}
```

- 이름은 넣지 않는다(`alias: "학생"`). 화면에서 교사가 볼 때만 실제 이름을 쓴다.
- 고르는 규칙: 그 교과 성취기준이 붙은 관찰 → 그 교과 성격 태그(바: 실천·습관·배려·안전, 슬: 탐구·질문, 즐: 놀이·표현·협력)가 붙은 관찰 → 나머지. 최대 12개, 주제책이 고르게 섞이도록. 바른 생활에는 습관 실천율을 넣는다.
- `text`는 교사 메모, `quote`는 교사가 확인한(고친 것 포함) 자막에서 앞 80자. 자막 상태가 `done`이 아니면 넣지 않는다.
- `together`: 여러 학생이 함께 기록된 관찰(다른 학생 정보는 넣지 않고 표시만).
- 근거가 3개 미만이면 "기록이 부족합니다(N개). 이 교과 관찰 기록을 더 남겨 주세요"를 돌려주고 초안을 만들지 않는다.

## (2) 초안 생성 — 출력 형식

```json
{
  "sentences": [
    { "text": "궁금한 것이 생기면 '왜 그럴까?' 질문하며 우주와 별을 영상 자료로 찾아보았음.", "evidence": ["o:3f2a…"] },
    { "text": "마을 안전 지도를 만들며 등굣길의 위험한 곳을 살펴보고 친구들과 의견을 나눔.", "evidence": ["s:77de…"] }
  ]
}
```

- 문장 2~4개, 전체 250자 안팎(설정으로 바꿀 수 있음). 종결은 "~함", "~음" 등 교사가 고른 문체(설정, 기본 "~함").
- **템플릿 생성기(지금 구현)**: 근거 종류·태그·성취기준별 문장 틀(데이터 파일 `data/evaluation/templates.json`)에 근거의 주제·활동·메모 핵심을 넣는다. 결과는 딱딱하지만 근거 연결과 화면 흐름을 미리 쓸 수 있고, 언어 모델을 못 쓰는 PC의 대체 수단이 된다.
- **언어 모델 생성기(나중)**: llama.cpp `llama-server`에 위 JSON 형식을 강제하는 JSON 스키마(문법 제약 출력)를 걸어, 근거 id가 아닌 문자열이 나올 수 없게 한다. 학습은 아래 「학습 데이터 계획」.

## (3) 자동 검사 — `check_draft`

문장마다 경고를 붙인다(차단이 아니라 표시, 교사가 판단).

| 검사 | 기준 |
|---|---|
| 근거 없음 | `evidence`가 비었거나 묶음에 없는 id |
| 금지 표현 | `data/evaluation/forbidden.json`의 낱말·정규식(서열, 사교육·기관명 유형, 가족 직업·경제 표현, 부정적 낙인 표현). 교사가 항목을 더할 수 있음 |
| 다른 학생 이름 | 학급 명단의 다른 학생 이름이 들어 있음(두 글자 이상 이름 기준) |
| 근거와 다른 내용 | 문장의 주제책·활동 낱말이 가리킨 근거 어디에도 없음(낱말 겹침이 0이면 "근거와 맞는지 확인") |
| 길이 | 설정 범위 밖 |

## (4) 화면 — 「평어」 탭

- 학급·교과·기간(학기) 선택 → 학생 목록(근거 개수, 상태: 없음·초안·확정).
- 학생 하나: 왼쪽 근거 목록(체크로 빼거나 넣기, 누르면 원래 기록 보기), 오른쪽 초안 문장(문장마다 근거 칩, 경고 표시) → 문장 편집·삭제·추가(추가한 문장도 근거 칩을 하나 이상 붙여야 확정 가능) → 「확정」.
- 확정본 「복사」(NEIS에 붙여넣기). 학급 전체 확정본을 텍스트 파일로 내보내기(번호·이름·교과·평어).
- 저장: 새 표 `evaluation_drafts`(학생·교과·기간·문장 JSON·상태·생성기 종류·확정 시각).

## 학습 데이터 계획 (로컬 언어 모델용, 뒤 단계)

| 단계 | 내용 | 누가 |
|---|---|---|
| A. 교사 예시 | 실제처럼 쓴 평어 50~100개(실명·실제 학생 정보 없이). 교과별, 문체 다양하게 | **사용자(교사)** |
| B. 합성 근거 묶음 | 활동 카드·놀이 카드·성취기준으로 가짜 학생 기록을 코드로 생성(1,000~3,000개) | Haiku 워커(스크립트) |
| C. 목표 출력 | 큰 클라우드 모델이 A의 문체와 위 원칙으로 B에 대한 평어 작성(가짜 데이터만 보냄) | 별도 실행 |
| D. 검수 | 200~300개를 교사가 검토·수정 → 평가용 100개는 따로 보관 | 사용자 + 메인 세션 |
| E. 학습 | 한국어 가능한 3B급 공개 모델에 LoRA, 양자화(GGUF Q4_K_M) | 메인 세션 설계, 실행은 GPU 빌려서 |
| F. 평가 | 근거 연결 100%, 금지 표현 0, 교사 평가(자연스러움·정확성), 템플릿 대비 비교 | verifier + 사용자 |

모델 후보는 상업 배포 가능한 라이선스만 쓴다(학습 시점에 다시 확인).

## 이번 구현 범위

(1) 근거 모으기, (2) 템플릿 생성기, (3) 자동 검사, (4) 화면과 저장, 금지 표현·템플릿 데이터 파일과 스키마.
언어 모델 연결, 학습 데이터 생성 스크립트는 다음 설계에서 한다.

## 사용자에게 받을 것

- 학교에서 쓰는 평어 문체(예: "~함" / "~음" / "~하는 모습을 보임")와 교과별 대략적인 글자 수.
- 교사 예시 평어(A단계). 실제 학생 정보를 지운 것.
- 학교 기재요령에서 추가로 금지하는 표현이 있으면 그 목록.
