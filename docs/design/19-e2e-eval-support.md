# 설계 19: E2E — 통합 평어와 문의용 진단 파일

설계 15(진단 파일·오류 기록)와 18(세 교과 통합 평어)은 브라우저 가짜 invoke로만 확인했다. 실제 윈도우·WebView2에서 **클립보드 복사, 저장 대화상자 경로, 로그 파일 위치**를 확인한다. 설계 14의 장치(대화상자 대체 큐, 테스트 데이터 폴더)를 그대로 쓰고 릴리스 동작은 바꾸지 않는다.

## 시나리오 (`e2e/native.test.mjs`에 이어서, 또는 새 `e2e/eval.test.mjs` — `npm run e2e`에 추가)

1. **통합 평어**
   - 학급·학생 1명(기존 도우미 사용), 바·슬·즐 각각의 성취기준·태그가 붙은 관찰을 교과마다 3개 이상 저장(화면 또는 기존 도우미).
   - 「평어」 탭 → 기간 지정 → 바른 생활 → 템플릿으로 초안 만들기 → 확정. 슬기로운 생활, 즐거운 생활도 같게.
   - 「세 교과 합치기」 → 통합본 글상자에 세 교과 문장이 바→슬→즐 순서로 있음.
   - 「확정」 → 「복사」 → `navigator.clipboard.readText()`(executeScript; 권한 문제로 안 되면 Rust 쪽 확인 대신 화면의 「복사했습니다」 안내 + 디버그 전용 `window.__lastCopied` 기록을 확인)로 통합본과 같음.
   - 학급 내보내기 「통합본(NEIS용)」 → 저장 대체 경로 → 파일이 있고 UTF-8 BOM, 첫 줄 `번호\t이름\t성취수준 및 특기사항`, 둘째 줄에 통합본.
2. **진단 파일**
   - 「정보」 → 「문의용 진단 파일 만들기」 → 목록 확인 → 「만들기」(저장 대체 경로).
   - zip이 있고 항목이 `about.json`, `logs/app.log`(+돌린 로그)만(기기 점검 결과가 없으면 `diag/` 없음). PowerShell 없이 Node로 zip 중앙 디렉터리를 읽어 이름 목록 확인(압축 없는 zip이므로 간단).
   - `about.json`의 `appVersion`이 package.json 버전, 학생 수 1.
   - `logs/app.log` 안에 학생 이름(테스트 명단)이 **없음**, 「시작」 줄 있음.
3. **오류 기록 위치**: `TONGHAP_DATA_DIR`이 로컬 데이터 폴더 역할을 하므로 `<TONGHAP_DATA_DIR>/logs/app.log`가 생겼는지 확인.

## 필요하면 더할 디버그 전용 장치

- 클립보드를 E2E에서 읽을 수 없으면 `src/lib/clipboard.ts` 래퍼(모든 `navigator.clipboard.writeText` 호출을 모음)에서 디버그 빌드에서만 `window.__lastCopied`에 남긴다. E2E 앱은 `vite build` 결과를 쓰는 디버그 빌드일 수 있어 `import.meta.env.DEV`가 거짓일 수 있으니, 기존 디버그 전용 장치(예: Rust 명령이 `cfg!(debug_assertions)`로 알려 주는 값)로 판단한다. 릴리스 빌드에서는 동작하지 않아야 함.

## 테스트 기준

- 위 시나리오가 `e2e.yml` 수동 실행에서 통과.
- 기존 E2E 시나리오는 그대로 통과.
