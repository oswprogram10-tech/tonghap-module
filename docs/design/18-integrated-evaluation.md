# 설계 18: 세 교과 통합 평어

## 왜

「학교생활기록 작성 및 관리지침」(교육부훈령, 2026.3.1. 시행) 제15조 제2항: 초등학교 교과학습발달상황의 「성취수준 및 특기사항」은 교과별로 쓰되 **1·2학년 「바른생활」「슬기로운 생활」「즐거운 생활」은 통합하여 입력**한다. 기재요령은 "세 교과의 성취기준을 바탕으로 … 종합하여 기록하며, **특정 교과가 누락되지 않도록** 유의"하라고 한다. 서술형은 **명사형 어미로 종결**하고, 특수문자·번호 기호는 지양한다.

지금 앱은 바·슬·즐 평어를 따로 만들고 따로 복사한다. 선생님은 NEIS 한 칸에 셋을 이어 붙여야 하고, 길이(교과마다 기본 250자 → 합치면 750자)가 너무 길다.

## 바꾸는 것

생성과 근거 연결은 지금처럼 **교과별**로 한다(근거 묶음·검사·확정이 교과 단위라 누락을 막기 쉽다). 그 위에 **학생별 통합본**을 둔다.

### 1. 통합본 (새 마이그레이션 9 — 기존 항목 수정 금지)

```sql
CREATE TABLE evaluation_combined (
  id TEXT PRIMARY KEY,
  class_id TEXT NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  student_id TEXT NOT NULL REFERENCES students(id) ON DELETE CASCADE,
  period_from TEXT NOT NULL,
  period_to TEXT NOT NULL,
  text TEXT NOT NULL,
  source_hash TEXT NOT NULL,          -- 만들 때 쓴 세 교과 확정본의 해시(바뀌면 "교과 평어가 바뀌었습니다" 표시)
  status TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'confirmed')),
  confirmed_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (student_id, period_from, period_to)
);
```

- `evaluation_combine(studentId, from, to)`: 세 교과가 **모두 확정**이어야 만든다(아니면 "바른 생활 평어를 먼저 확정해 주세요"처럼 빠진 교과를 알려 줌). 순서 바 → 슬 → 즐, 각 교과의 문장을 공백 하나로 이어 한 문단으로. 교과 이름이나 기호(「바른 생활:」, 번호, 줄머리표)는 넣지 않는다.
- 이미 있으면 덮어쓰기 전에 확인(화면). 선생님이 고친 통합본을 잃지 않게 한다.
- `evaluation_combined_save(id, text)`: 선생님이 문장을 다듬는다. 저장하면 상태는 `draft`.
- `evaluation_combined_check(text)`: 기존 검사 재사용(금지 표현, 다른 학생 이름) + 새 검사
  - **명사형 종결**: 문장(마침표 기준)이 「함·음·임·됨·보임·했음·하였음…」처럼 명사형으로 끝나는지. 아니면 경고 「명사형 어미(~함, ~음)로 끝내 주세요」.
  - **특수문자·번호**: `①`, `1.`, `-`, `•`, `*`, `※`, 이모지로 시작하는 줄이나 이런 기호가 있으면 경고.
  - **길이**: 글자 수와 NEIS 바이트(한글 3, 영문·숫자 1, 줄바꿈 1)를 늘 보여 준다. 500자를 넘으면 안내 「학교 방침에 맞는지 확인하세요(2024 기재요령 기준 교과별 500자, 2026 초등 기재요령은 시스템 범위 안에서 별도 제한 없음)」. 차단하지 않는다.
  - **교과 누락**: 통합본을 고치다 한 교과에서 온 문장을 모두 지웠는지는 알 수 없으므로, 대신 만들 때 그 교과에서 온 문장이 하나도 그대로 남지 않았으면 「○○ 생활 내용이 빠진 것 같습니다」 경고(문자열 포함 여부로 단순 판단).
- `evaluation_combined_confirm(id)`: 경고 중 금지 표현·다른 학생 이름이 있으면 확정 불가(기존 교과 확정 규칙과 같음). 확정해야 복사·내보내기.
- 교과 평어를 다시 고쳐 확정하면 `source_hash`가 달라져 통합본에 「교과 평어가 바뀌었습니다. 다시 합치기」 표시(자동으로 덮지 않음).

### 2. 기본 길이

- 교과별 목표 글자 수 기본값 250 → **150**(세 교과 합쳐 약 450자). 허용 범위 `LEN_MIN` 150 → **80**, `LEN_MAX` 400 유지. 이미 저장된 설정값은 바꾸지 않는다.
- 설정 화면 문구: 「교과별 목표 글자 수(세 교과를 합친 통합본은 약 3배)」.
- 언어 모델 프롬프트(`data/evaluation/prompt.json`)의 분량 문구는 그대로 `{target}`을 쓰므로 데이터 수정 없음.

### 3. 화면 (`src/evaluation/`)

- 학생 평어 화면 아래에 「통합본(NEIS 입력용)」 칸: 세 교과 확정 상태(✓/미확정) → 「세 교과 합치기」 → 고칠 수 있는 글상자, 글자 수·바이트, 경고 목록, 「확정」, 「복사」.
- 교과별 「복사」는 남겨 두되 문구를 「이 교과만 복사」로, 옆에 안내 「NEIS에는 통합본을 붙여 넣습니다」.
- 학급 목록에 학생별 통합본 상태 열(없음/초안/확정).
- 칸 이름은 기재요령 용어 「성취수준 및 특기사항」을 쓴다.

### 4. 내보내기

- 학급 내보내기(.txt)에 선택: 「통합본(NEIS용)」(기본) — `번호\t이름\t성취수준 및 특기사항` / 「교과별」 — 지금 형식. 통합본은 확정한 것만.

## 테스트 기준

- 세 교과 중 하나라도 미확정이면 합치기 거부, 빠진 교과 이름이 오류에 있음.
- 합친 결과에 교과 이름·기호 없음, 순서 바→슬→즐.
- 명사형 종결 검사: 「~함.」「~하였음.」「~하는 모습을 보임.」 통과, 「~했다.」「~합니다.」 경고.
- 특수문자 검사, 바이트 계산(한글 3, 영문·숫자 1).
- 교과 평어를 다시 확정하면 통합본이 「바뀜」 상태, 통합본 글은 그대로.
- 금지 표현이 있으면 확정 불가. 확정 전 복사 불가.
- 내보내기 두 형식.
- 마이그레이션 9가 8에서 데이터를 지키며 올라감.
