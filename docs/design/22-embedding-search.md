# 설계 22: 학생 질문 묶기와 뜻으로 찾는 활동 추천 (임베딩)

`docs/PLAN.md` 로컬 AI 계획의 「질문 묶기·활동 추천: 임베딩 검색 + 규칙」. 지금 추천(설계 10)은 질문 낱말이 카드 키워드와 같을 때만 점수를 준다. "개미는 왜 줄 서요?"와 「곤충 관찰」 카드처럼 낱말은 달라도 뜻이 가까운 것을 잇고, 학생 질문 여러 개를 비슷한 것끼리 묶는다.

## 1. 모델

- `intfloat/multilingual-e5-small`(MIT, 384차원)의 GGUF Q8_0: `https://huggingface.co/TwinSunsLLC/multilingual-e5-small-gguf/resolve/main/multilingual-e5-small-q8_0.gguf`, 132MB, SHA-256 `e011debc1208e31bf7b6aebee2d9fc8bd2ca11694a77ed66ac9d0c9d0a877c93`(내려받아 직접 확인하고 다르면 멈춰 보고).
- `src-tauri/src/diag/mod.rs`의 `MODELS`에 `e5-small-q8` 추가(이어받기·파일 선택·해시 확인 그대로). 「기기 점검」 모델 목록에 「질문 묶기·활동 추천(선택, 약 130MB)」.
- 모델 라이선스 고지(MIT, intfloat, GGUF 변환 TwinSunsLLC)를 정보 화면 모델 라이선스와 `THIRD_PARTY_NOTICES.md`에.
- E5 규칙: 입력 앞에 `query: `(질문·묶기) / `passage: `(카드 본문). 평균 풀링, L2 정규화.

## 2. 실행

- 이미 있는 `llama-server.exe`를 임베딩 전용으로 따로 띄운다: `--embedding --pooling mean -c 512 -ngl 0`(CPU로 충분), 127.0.0.1, 남는 포트, 설계 09의 서버 관리(Job Object, 끝날 때 종료)를 재사용. 평어 서버와 따로 관리하고 5분 동안 안 쓰면 끈다.
- 요청: `POST /embedding`(또는 `/v1/embeddings`) — llama-server b11600에서 실제로 되는 쪽을 엔진 테스트로 확인해 하나만 쓴다.
- 모델이 없거나 서버가 실패하면 **지금의 규칙 방식 그대로**(오류 화면 없음, 추천 이유에 뜻 기반 항목만 빠짐).

## 3. 카드 벡터 저장 (마이그레이션 10, 끝에 추가만)

```sql
CREATE TABLE embeddings (
  kind TEXT NOT NULL,          -- 'card'
  ref_id TEXT NOT NULL,        -- 카드 id(기본·교사 카드)
  model TEXT NOT NULL,         -- 'e5-small-q8'
  text_hash TEXT NOT NULL,     -- 임베딩한 글의 SHA-256 앞 16자리
  vec BLOB NOT NULL,           -- f32 리틀엔디언 384개
  PRIMARY KEY (kind, ref_id, model)
);
```

- 카드 글 = `passage: ` + 제목 + 활동 요약 + 키워드. 해시가 다르면 다시 계산. 처음 한 번 96장 계산(배치로).
- 학생 질문 벡터는 저장하지 않는다(그때그때 계산, 질문은 짧음). 아이 말이 DB 밖 파일에 남지 않게.

## 4. 추천 점수 (`activity_recommend` 확장)

- 지금 점수(낱말 일치 +3/낱말, 성취기준, 안전·메이킹북 등)는 그대로 두고, 질문이 있고 모델이 있으면 **뜻 점수**를 더한다: 질문들(각각 `query: `) 벡터와 카드 벡터의 코사인 최댓값 `s`. 같은 주제책 카드 안에서 순위를 매겨 상위 3장에 각각 +4, +3, +2(절댓값 문턱은 쓰지 않음 — e5는 관련 없는 글도 0.7대라 순위만 믿는다). 이유 문구: 「학생 질문 '…'과 뜻이 가까워요」(질문 앞 20자).
- 결정적: 같은 입력이면 같은 결과(동점은 기존 규칙대로).

## 5. 질문 묶기

- 꼬리 잇기 창(설계 03·10)의 학생 질문 칸에 질문을 줄마다 여러 개 적으면 「비슷한 질문 묶기」 단추. 모델이 있을 때만 보임.
- 방법: 질문 벡터의 코사인 유사도로 단순 묶기(평균 연결 계층 묶기, 문턱은 질문들 사이 유사도 분포의 상위 사분위 기준 — 고정 문턱 금지, 근거 주석). 묶음마다 질문 목록과 개수, 대표 질문(묶음 중심에 가장 가까운 것).
- 묶음을 누르면 그 묶음 질문들로 추천을 다시 받는다.
- 결과는 화면에만(저장하지 않음). 차시에 저장되는 것은 지금처럼 선생님이 고른 질문 글.

## 테스트 기준

- 단위: 코사인·정규화, 묶기(만든 벡터로 기대 묶음), 점수 합산과 순위 가점, 모델 없음 → 기존 결과와 완전히 같음(기존 추천 테스트 그대로 통과), 카드 해시 바뀌면 다시 계산, 마이그레이션 10(9에서 데이터 유지).
- 엔진 통합 테스트(`src-tauri/tests/engines.rs`, 윈도우): e5 모델을 받아 서버를 띄우고 384차원, 「개미는 왜 줄을 서서 가요?」가 「곤충 관찰」류 문장에 「태극기 그리기」보다 가깝다, 끝나면 프로세스가 남지 않음. `engines.yml`에 모델 내려받기(해시 확인, 캐시) 추가.
- 화면: 모델 없을 때 묶기 단추 없음, 있을 때 묶음 표시(가짜 invoke 스모크).
