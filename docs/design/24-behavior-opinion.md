# 설계 24: 행동특성 및 종합의견 초안, 그리고 AI 문장 확인 장치

## 근거 (2026학년도 학교생활기록부 기재요령·지침)

- 지침 제16조 ①: 학년 동안 지속적으로 관찰한 행동특성을 바탕으로 학생을 총체적으로 이해할 수 있는 종합의견을 **학급 담임교사가 문장으로** 입력한다.
- 해설: 학습·행동·인성 등 학교생활 전반의 누가기록을 바탕으로 구체적인 변화와 성장을 종합 기재. **장점과 단점은 누가 기록된 사실에 근거**하고, **단점을 쓸 때는 변화 가능성을 함께** 입력. 학기를 나눠 쓸 수 있으며 그때는 「(1학기)」「(2학기)」를 직접 붙인다.
- 초등은 이 칸의 글자 수 제한이 없음(시스템 범위 안). 바이트: 한글 3, 영문·숫자 1, 줄바꿈 1.
- 서술형은 명사형 어미로 끝내고 특수문자·번호 기호는 지양.
- **「AI를 활용하여 생성한 자료를 서술형 항목에 그대로 입력하는 행위」 금지.** 윤문 등 보조 수단으로 쓸 때는 최종 입력 전에 실제 수행과 무관한 허위·과장이 없는지, 기재요령을 지켰는지 철저히 확인(2026 기재요령 「작성 시 유의사항」 4항 다목). → 이 앱의 모든 초안(교과·통합본·행발)에 확인 장치를 둔다(아래 5).
- 대회·수상, 자격증, 부모 직업·지위, 기관·상호명 등 기재 금지 사항은 기존 금지 표현 목록과 같다.

## 1. 기록 쪽 보강

- 활동 태그에 「책임」「존중」「성장」 추가(기존 9개 뒤). 평어 템플릿의 태그 묶음에도 연결(바: 책임·존중 → 실천/배려 계열).
- 관찰 기록에 선택 표시 **「지도가 필요한 모습」**(`needs_guidance` 0/1). 선생님이 단점으로 볼 만한 행동을 남길 때 켠다. 기록 목록에 작은 표시. 학부모 리포트(설계 07)에서는 이 기록을 **기본으로 뺀다**.
- 주제책 없이 남기는 생활 기록은 이미 가능(주제책 칸 비움). 화면에 「생활(주제책 없음)」 선택지로 분명히 보인다.
- 마이그레이션 11(끝에 추가만): `observations.needs_guidance INTEGER NOT NULL DEFAULT 0`, 아래 2의 표.

## 2. 근거 묶음과 저장

- `behavior_bundle(studentId, from, to)`: 기간의 그 학생 관찰 **전체**(교과 무관)에서 고른다. 우선순위: 인성·생활 태그(배려·협력·존중·책임·습관·안전·실천·성장) → 「지도가 필요한 모습」 → 그 밖. 최대 14개, 학기·주제책이 고르게. 습관 실천율(기간), 「지도가 필요한 모습」 기록 이후 같은 태그의 긍정 기록이 있으면 짝으로 묶어 표시(변화 근거).
- 근거 형식은 설계 08의 근거 묶음과 같고 `negative: true` 필드만 더한다. 이름은 「학생」, 다른 아이는 「친구」.
- 근거 3개 미만이면 초안을 만들지 않는다.
- 표 `behavior_opinions`: `id, class_id, student_id, period_from, period_to, split_semesters INTEGER, sentences TEXT(JSON: text, evidence[], reviewed bool), generator, generated_text TEXT(만든 그대로의 글), status draft|confirmed, confirmed_at, created_at, updated_at, UNIQUE(student_id, period_from, period_to)`.

## 3. 초안 만들기

- **템플릿**: `data/evaluation/behavior-templates.json`(스키마·검증 포함). 장점(태그별), 성장·변화(짝 근거), 단점+변화 가능성(「…하는 때가 있었으나 … 노력하여 점차 …함」, 「…를 꾸준히 연습한다면 … 기대됨」) 틀. 모든 틀은 근거 메모(`{note}`)를 반드시 쓴다.
- **언어 모델**: 설계 09의 서버·JSON 스키마(근거 id enum) 그대로. 프롬프트는 `data/evaluation/behavior-prompt.json`(기존 prompt.json 구조 재사용): 담임 종합의견의 성격, 장점·성장 중심, 단점에는 반드시 변화 가능성, 근거에 없는 성격·가정 상황 금지, 명사형 종결, 목표 글자 수.
- 학기 나누기를 켜면 1학기·2학기 근거를 따로 묶어 만들고 각 덩어리 앞에 「(1학기)」「(2학기)」를 붙인다(특수문자 검사에서 이 두 표기는 예외).
- 목표 글자 수 기본 300자, 범위 150~800(설정). 화면에 글자 수·NEIS 바이트.

## 4. 검사 (`check` 재사용 + 추가)

- 기존: 금지 표현, 다른 학생 이름, 근거 없는 문장, 명사형 종결, 특수문자·번호.
- 추가: **단점 문장의 변화 가능성** — `negative` 근거를 가리키는 문장에 변화·노력 표현(노력, 점차, 나아지, 성장, 기대, 꾸준히, 연습 등 — 목록은 데이터 파일)이 없으면 경고 「단점을 쓸 때는 변화 가능성을 함께 써 주세요(기재요령)」.
- 추가: 단점 문장만 있고 장점·성장 문장이 없으면 경고.

## 5. AI 문장 확인 장치 (교과 평어·통합본·행발 모두)

- 초안의 문장마다 **「근거 확인」** 체크. 문장 옆 근거 기록을 펼쳐 보고 선생님이 체크한다. 문장을 고치면 그 문장 체크는 유지(선생님이 쓴 것), 새 문장을 더하면 체크된 상태로 시작.
- 모든 문장이 체크되어야 「확정」 가능. 버튼 옆 안내: 「AI나 템플릿이 만든 문장을 그대로 입력하지 않도록 2026 기재요령이 정하고 있습니다. 근거와 실제 모습을 확인해 주세요.」
- 언어 모델이 만든 글을 **한 글자도 고치지 않고** 확정하려 하면 확인 창: 「언어 모델이 만든 문장을 고치지 않았습니다. 기재요령은 AI가 만든 문장을 그대로 입력하지 않도록 합니다. 그대로 확정할까요?」(선생님 판단으로 진행 가능, 막지는 않음). 비교는 `generated_text`와 현재 글.
- 기존 교과 평어 표(`evaluation_drafts`)와 통합본에도 문장별 `reviewed`와 `generated_text`를 더한다(마이그레이션 11에서 칼럼 추가, 기존 확정본은 `reviewed=true`로 간주).

## 6. 화면 (`src/evaluation/`)

- 「평어」 탭 위쪽 전환: **「교과 (성취수준 및 특기사항)」** / **「행동특성 및 종합의견」**.
- 행발 화면: 학생 목록(상태), 근거 목록(「지도가 필요한 모습」은 표시), 학기 나누기 켬/끔, 초안 만들기(템플릿/언어 모델), 문장 편집·근거 확인 체크, 검사 경고, 확정·복사, 학급 내보내기(`번호\t이름\t행동특성 및 종합의견`).
- 64px 터치, 한국어 문구.

## 테스트 기준

- 마이그레이션 11(10에서 데이터 유지, 기존 확정본 reviewed=true).
- 근거 묶음: 교과 무관 수집, 우선순위, negative 표시, 짝 근거, 3개 미만 거부, 이름 가림.
- 템플릿: 결정적, 모든 문장 근거 있음, 단점 문장은 변화 표현 포함, 학기 나누기 접두.
- 검사: 변화 가능성 경고, 장점 없음 경고, 「(1학기)」 예외.
- 확인 장치: 미체크 문장 있으면 확정 거부, 체크 유지 규칙, LLM 글 그대로면 확인 필요 플래그(백엔드는 `unchangedFromModel: bool`을 돌려주고 화면이 확인 창), 교과·통합본에도 적용.
- 리포트: 「지도가 필요한 모습」 기록은 기본 제외.
- 내보내기, 스모크(가짜 invoke), 기존 테스트·E2E 유지(E2E 평어 시나리오는 확정 전에 「근거 확인」을 누르도록 함께 고침).
